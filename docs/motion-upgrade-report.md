# Система движения «СтеклоФурнитура»

Исходная версия f9f50e5. Резервная ветка `backup/pre-motion-upgrade-2026-11-09`.
Разработка — `design/motion-upgrade`. Работа выполнена одним агентом.
Архитектурный дизайн, цвета, данные, 1463 товара, URL и бизнес-логика сохранены.

## Исходное состояние

Общие hover-переходы присутствовали, но меню и уведомления имели только простое
появление. Закрытие было мгновенным. Выбор фотографии менял src без контролируемого
перехода, сортировка переставляла карточки скачком. Класс `is-added` назначался,
но не обеспечивал полноценного состояния подтверждения. Не было общей отмены
анимаций при быстрых действиях и переключении accessibility-настройки.

## Единая система

CSS-переменные задают длительности, JS читает те же токены. Общая кривая —
`cubic-bezier(.22,.72,.24,1)`. Нажатие/hover — 140–220 ms, состояния — 200–280 ms,
меню — 240/160 ms, диалог — 260 ms, сортировка — до 300 ms, появление секций —
480 ms, декоративное движение фото — 550 ms. Переход страницы — 180 ms.

Используются CSS и Web Animations API без новой runtime-библиотеки.
Анимируются в основном opacity, transform/translate/scale. Ширина и высота
страницы не анимируются. Нет scroll hijacking, тяжёлого blur, постоянного
параллакса, пульсаций маркера или постоянного `will-change`.

Предыдущая анимация одного элемента отменяется при новом действии. Ожидаемые
отказы `Animation.finished` при cancel обработаны, без unhandled rejection.
Учитывается [поведение Web Animations API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Animations_API/Using_the_Web_Animations_API).

## Что изменилось

- **Кнопки:** короткое нажатие, согласованные цвет/граница/стрелка, видимый фокус;
  размеры кнопок добавления стабилизированы между состояниями.
- **Добавление:** сразу «Добавляем…» и disabled/busy; после фактического сохранения
  «Добавлено ✓», подтверждение цветом, мягкое обновление счётчика, уведомление.
  При сетевой ошибке — «Повторить» и текстовое сообщение, без ложного успеха.
  Повторные действия не повреждают исходную подпись кнопки.
- **Меню:** мягкий вход и полноценный визуальный выход. Логическое скрытие,
  aria-expanded и фокус меняются сразу; короткий уходящий снимок inert/aria-hidden,
  без ID и action-атрибутов, не перехватывает ввод и автоматически удаляется.
  Быстрое повторное открытие удаляет старый снимок. Приложение исключает снимки
  из своих селекторов, включая поиск целевого элемента для возврата фокуса.
- **Карточки/категории:** согласованы фотография, стрелка, подпись и граница;
  сенсорный режим не оставляет перемещение/тени hover. Важные действия не ждут эффектов.
- **Галерея:** загружается только выбранный следующий файл, прежняя фотография
  остаётся до готовности новой. Номер выбора защищает от запоздалого load.
  При ошибке остаются прежние изображение/ссылка увеличения и корректная активная
  миниатюра, показывается сообщение. Вход/выход диалога и фон смягчены;
  Escape освобождает диалог и возвращает фокус сразу.
- **Заявка:** счётчик обновляется с коротким откликом; при удалении уходящая строка
  не блокирует действие, оставшиеся строки мягко занимают своё место.
- **Сортировка:** FLIP только для видимых элементов, максимум 24. Дальние элементы
  появляются на новом месте коротко, вместо полёта через всю длинную страницу.
- **Поиск:** исходные loading/error/retry сохранены, готовые результаты мягко проявляются.
- **Уведомления:** вход/выход и плавное обновление уже видимого сообщения,
  без повторного исчезновения в ноль; одно действительное aria-live-сообщение.
  Таймер по-прежнему учитывает фокус и наведение, ссылка на заявку сохранена.
- **Секции:** умеренное одноразовое появление крупных блоков. Товарные карточки
  каталога по отдельности не наблюдаются, максимум 96 крупных целей.
  Нет скрытого pending-контента: без JS/IntersectionObserver/WAAPI всё видно.
- **Формы:** плавная граница/подсветка фокуса, native validation и текстовые сообщения
  сохранены; invalid не обозначается одним цветом, длительного shake нет.
- **Карта:** сохранён Leaflet; улучшены состояния кнопок и маркера, текст загрузки.
  Успешная загрузка обновляет статус один раз, а не при каждом tileload.
  Адрес, маршрут, zoom, pan, reset и fallback сохранены.
- **Страницы:** нативный same-origin crossfade через CSS `@view-transition`.
  Никакого перехвата ссылок/нового роутера. Неподдерживающие браузеры сохраняют
  обычную навигацию. [Требования к opt-in обеих страниц](https://developer.mozilla.org/en-US/docs/Web/CSS/@view-transition).

## Reduced motion

Настройка учитывается при загрузке и меняется во время работы: JS-анимации
отменяются, временные снимки удаляются, наблюдение отключается. CSS убирает
декоративные перемещения, масштабирование, плавную прокрутку и переходы страниц.
Метка карты сохраняет свою базовую геометрию. Успех/ошибка, сообщения, меню,
галерея и работа с заявкой остаются доступными без движения.

## Визуальная проверка и измерения

Записаны реальные браузерные взаимодействия: [до](motion-upgrade/preview-before.webm)
и [после](motion-upgrade/preview.webm). В роликах меню, категории, карточки,
добавление/уведомление, переход страницы и галерея. Дополнительно просмотрены
контрольные кадры, проверены состояния и жизненный цикл анимаций браузерными тестами.

[Сенсорная проверка](motion-upgrade/browser-results.json),
[сравнение frame samples](motion-upgrade/frame-samples.json),
[переходы страниц](motion-upgrade/navigation.json).

Один лабораторный прогон Chromium при CPU ×4, 375×850, четыре цикла меню:

| rAF интервал | До | После |
|---|---:|---:|
| Средний | 16.87 ms | 16.66 ms |
| P95 | 16.8 ms | 16.7 ms |
| Максимальный | 50 ms | 33.3 ms |

Это выборка requestAnimationFrame конкретного облачного Chromium, **не**
сертификат 60 FPS, не измерение compositor throughput и не гарантия на физических
Android/iPhone. Idle-выборка в browser-results также не используется как доказательство
скорости анимаций. Реальные iOS/Safari/Firefox и low-end устройства отдельно не измерялись.

Самооценка: до — примерно 6.5/10 за отсутствие цельного завершения действий;
